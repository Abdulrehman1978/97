## 1. Host Recovery & Root Cause Analysis

### 1.1 Initial Failure Diagnosis
Docker Desktop failed to start with Windows Hyper-V Compute System (HCS) error:
```text
Wsl/Service/CreateInstance/CreateVm/HCS/0x800705aa
Insufficient system resources exist to complete the requested service.
```

### 1.2 Root Cause
1. **Unbounded WSL2 Default Memory Allocation**: Host system possessed 15.38 GB total RAM. Without a bounded configuration, WSL2 default attempted to reserve 50% (~7.69 GB) of host RAM.
2. **Commit Pressure & Zombie Processes**: Host physical free memory was depressed to ~2.69 GB with ~1.65 GB committed to zombie processes (`com.docker.backend.exe` PID 28732 and associated handles from prior crashed launches).
3. When `wsl.exe -d docker-desktop` was invoked, `vmcompute` (Hyper-V Host Compute Service) refused VM memory allocation with error `0x800705aa`.

### 1.3 Safe, Non-Destructive Remediation Actions
Strict compliance with non-destructive constraints (no `wsl --unregister`, no deletion of `ext4.vhdx`, no factory reset):
1. **Process Cleanup**: Gracefully terminated stale Docker processes (`com.docker.backend`, `docker-index`, `Docker Desktop.exe`).
2. **WSL Reset**: Executed `wsl --shutdown` to cleanly flush WSL VM states and reclaim locked memory. Free physical memory expanded immediately from 2.69 GB to 5.45 GB.
3. **Resource Bounding Configuration**: Created `C:\Users\a\.wslconfig`:
   ```ini
   [wsl2]
   memory=6GB
   processors=4
   swap=8GB
   ```
4. **Service Verification**: Confirmed `vmcompute`, `WslService`, and `LxssManager` are active and responsive.
5. **Daemon Launch**: Launched Docker Desktop (`C:\Users\a\AppData\Local\Programs\DockerDesktop\Docker Desktop.exe`).
6. **Engine Verification**:
   - `docker version`: Client 28.5.1 / Server Engine 29.8.0 active
   - `docker info`: 4 CPUs, 5.788 GiB Total Memory, operating cleanly on context `desktop-linux`
   - `wsl -l -v`: `docker-desktop` distro running on WSL version 2
