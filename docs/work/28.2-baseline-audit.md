## Gaps Found at Audit Start (Packet 28.2 Scope)

### GAP-1: No authenticated session system  
**Severity:** CRITICAL  
**Detail:** No login page, no AuthProvider, no `useAuth()` hook. Frontend had no concept of the distinction between checking / authenticated / unauthenticated / forbidden states.

### GAP-2: Silent demo Ramesh fallback in production  
**Severity:** HIGH  
**Detail:** `interview/page.tsx` on backend failure silently wrote `demo-beneficiary-id` to localStorage and navigated forward. A judge auditing production would see demo data with no indication it was not real.  
`passport/page.tsx` silently retained Ramesh's seed data on API failure with no error indicator.

### GAP-3: No login/logout in Navbar  
**Severity:** HIGH  
**Detail:** The Navbar had a static role-switcher with no awareness of authentication state. There was no Sign In button for unauthenticated users, no user display for authenticated users, no logout.

### GAP-4: `datetime.utcnow()` DeprecationWarning in Python 3.12+  
**Severity:** MEDIUM (warning noise in CI)  
**Detail:** `journey/router.py`, `opportunities/router.py`, `intelligence/constraints.py` used deprecated `datetime.utcnow()`. One test additionally broke because of a naive-vs-aware datetime comparison when the code was partially updated.

### GAP-5: Uncommitted backend security hardening  
**Severity:** HIGH  
**Detail:** Correct ownership checks using `is_beneficiary_owner()` existed in the working tree but had not been committed. These included: checking `Beneficiary.user_id == User.id` (not `Beneficiary.id == User.id`) in journey/beneficiary routers.
